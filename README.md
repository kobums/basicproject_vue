# basicproject_vue

gomachine 표준 Vue 시작 프로젝트. gomachine 이 만든 백엔드(Go `basicproject_go`, Spring `basicproject_springboot`, Rust)에
붙는다. 세 백엔드는 같은 HTTP 계약(gomachine README "HTTP 계약")을 따르므로 프록시 주소만 바꾸면 된다.

- 게시판 / 회원 화면은 gomachine 이 생성한 모델 · 타입 · composable 을 쓴다.
- 인증(로그인 / 회원가입 / 내 정보), Pinia 인증 스토어, UI 컴포넌트(`src/components`)는 손으로 만든 코드다.

## 기술 스택

- Vue 3 + TypeScript 6 + Vite 8
- vue-router 5 (라우팅 + 인증 가드, 사용법은 4 와 같다)
- Pinia (전역 상태: `stores/auth.ts`, `stores/feedback.ts`, `stores/loading.ts`)
- axios 없음 — fetch 래퍼 `src/services/api.ts` 하나만 쓴다
- vitest + happy-dom (테스트), eslint + prettier

## 빠른 시작

```bash
npm ci
npm run dev        # http://localhost:5173 (/api, /uploads 는 VITE_PROXY_TARGET 으로 프록시, 기본 Go :8007)
```

백엔드를 먼저 띄운다 (DB 는 gomachine `bootstrap/docker-compose.yml` + `bootstrap/db/schema.sql`).

| 백엔드 | 기본 주소 | `.env.local` |
|---|---|---|
| Go (`basicproject_go`) | `http://localhost:8007` | (기본값) |
| Spring Boot (`basicproject_springboot`) | `http://localhost:8081` | `VITE_PROXY_TARGET=http://localhost:8081` |
| Rust (gomachine `main.rs`, `PORT` 기본 8080) | `http://localhost:8080` | `VITE_PROXY_TARGET=http://localhost:8080` |

```bash
npm run typecheck  # vue-tsc
npm run lint       # eslint (src, tests)
npm run format:check
npm test           # vitest
npm run build      # 타입체크 + 프로덕션 빌드
```

Node `^22.13 || ^24 || >=26` (vitest 5 / eslint 10 / vite 8 의 공통 범위).

## 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `VITE_API_BASE_URL` | `/api` | API 주소 앞부분 (`src/services/api.ts`). 프록시 대신 백엔드를 직접 부르려면 `http://localhost:8007/api` (백엔드 CORS 필요) |
| `VITE_PROXY_TARGET` | `http://localhost:8007` | dev 서버 프록시 대상 (`vite.config.ts`). `/api`, `/uploads` 를 넘긴다 |

- `.env` 는 공개 기본값만 담아 커밋한다. 개인 설정은 `.env.local` (`.env.local.example` 참고, 커밋 안 함).
- `VITE_*` 는 번들에 그대로 들어간다. 시크릿을 넣지 않는다.

## 디렉터리

| 경로 | 종류 | 내용 |
|---|---|---|
| `src/types/{user,board}.ts` | **생성** | 엔티티 타입, `Create/Update*Request`, `*SearchParams` |
| `src/models/{user,board}.ts` | **생성** | `UserModel` / `BoardModel` (`find`, `findpage`, `findall`, `get`, `count`, `insert`, `update`, `patch`, `remove` ...) |
| `src/models/contract.ts` | **생성** | Go / Spring 응답 정규화 (`Page<T>`, `ApiError`) |
| `src/composables/use{User,Board}.ts` | **생성** | `items`, `item`, `total`, `loading`, `error`, `fetchPage`, `fetchAll`, `fetchOne`, `create`, `update`, `remove` |
| `src/services/api.ts` | 사용자 (gomachine 이 없을 때 한 번 만든다) | 유일한 HTTP 클라이언트. `get/post/put/patch/del` → `{data, status}`, `HttpError`, `setTokenProvider`, `setUnauthorizedHandler` |
| `src/api/auth.ts`, `src/api/upload.ts` | 손으로 | 인증 / 이미지 업로드 API (같은 클라이언트 사용) |
| `src/stores/auth.ts` | 손으로 | 로그인 상태, 토큰 · 401 연결 |
| `src/lib/` | 손으로 | 토큰 저장소, 날짜 / 이미지 주소, 에러 문구 |
| `gomachine/model.json` | 설정 | 이 프로젝트용 생성 설정 (아래) |

생성 파일 첫 줄은 `// Code generated by gomachine. DO NOT EDIT.` 이다. 고치지 말고 다시 생성한다.
화면에 맞는 로직은 페이지나 손으로 만든 파일에 둔다.

## 다시 생성하기

DB 스키마나 `model.json` 이 바뀌면 다시 만든다. 보통은 백엔드 프로젝트의 `model.json` 에서 `languages.vue` 를 켜고
`vueModelFilePath` 를 이 디렉터리로 두고 한 번에 생성한다. 이 프로젝트만 따로 만들 때는:

```bash
# DB 접속 정보는 환경변수로 (model.json 값보다 우선)
DB_HOST=127.0.0.1 DB_USER=project DB_PASSWORD=... buildtool-model gomachine vue
npm run lint && npm run typecheck && npm test
git diff src/types src/models src/composables
```

`gomachine/model.json` (경로는 이 파일 기준):

| key | 값 | 설명 |
|---|---|---|
| `vueModelFilePath` | `".."` | 생성 대상 = 이 프로젝트 루트 |
| `tsOutDir` | `"src"` | `src/types`, `src/models`, `src/composables`, `src/services` 아래에 만든다 |
| `tsSemicolons` | `false` | `.prettierrc.json` 의 `semi: false` 와 맞춘다 |
| `table[].join` | board → user | `Board.extra.user` (작성자) |
| `table[].session` | board.user = 로그인 id | 작성자는 서버가 채운다. 목록도 본인 글만 온다 |
| `table[].protect` | user.level | 클라이언트가 바꿀 수 없다 |

- `table` 설정은 백엔드 `model.json` 과 같아야 한다 (특히 `join` 이 없으면 `extra.user` 가 없다).
- 생성 디렉터리(`src/types`, `src/models`, `src/composables`)는 `.prettierignore` 에 있다 (생성기 출력은 줄 길이 80 에 맞추지 않는다).
  eslint 는 생성 파일도 검사한다.
- `src/services/api.ts` 는 이미 있으므로 다시 만들지 않는다. 처음부터 받으려면 지우고 생성한다.

## HTTP 계약 요약

- 목록 `GET /api/{table}?page=1&pagesize=10&orderby=id desc&{필터}` — page 는 **1 부터**. 결과는 `Page<T> {items, total}`
  (Go `{items, total}`, Spring `{content, totalElements}` 를 `contract.ts` 가 맞춘다). `Pagination` 컴포넌트도 1 부터다.
- 단건 `GET /api/{table}/{id}`, 생성 `POST`, 수정 `PUT` (보낸 필드만), 삭제 `DELETE /api/{table}/{id}`.
- 필터 이름 = JSON key (`title`, `name`, `email` ...). 문자열 필터는 정확히 일치(Go 는 일부 컬럼이 `like`).
- 에러: Spring 은 HTTP 상태 코드 → `HttpError`, Go 는 HTTP 200 + `code: "error" | "auth error"` → `ApiError`.
  생성 composable 은 둘 다 `error` 에 담는다. 화면 문구는 `lib/errors.ts` 의 `errorMessage()`.
- 생성 API 는 모두 로그인이 필요하다 (`auth: jwt`). 그래서 게시판 / 회원 화면은 라우터에서 로그인을 요구한다.

## 인증 흐름

```
main.ts → useAuthStore().init()
  ├ setTokenProvider(getToken)          토큰은 localStorage 'basicproject.token' (lib/authStorage.ts)
  ├ setUnauthorizedHandler(clear)       어느 요청이든 401 → 토큰 삭제 + 로그아웃
  └ 토큰이 있으면 GET /api/auth/me 로 사용자 복구 (라우터 가드가 waitForRestore() 로 기다린다)

로그인 / 회원가입 → POST /api/auth/login | /api/auth/signup → 토큰 저장 → 응답에 user 가 없으면 GET /api/auth/me
```

백엔드가 돌려줘야 하는 모양 (`src/api/auth.ts` 가 너그럽게 읽는다):

| 요청 | 본문 | 응답 |
|---|---|---|
| `POST /api/auth/login` | `{email, password}` | `{token, user?}` (`tokenType`, `expiresInMs` 등은 무시) |
| `POST /api/auth/signup` | `{email, name, password}` | `{token, user?}` |
| `GET /api/auth/me` | `Authorization: Bearer <token>` | 사용자 `{id, email, name, level?, createddate?}` |

- 토큰 key 는 `token` / `accessToken` / `access_token` 중 하나.
- Go 식 봉투 `{code: "ok", ...}`, `{code, item: {...}}`, `{data: {...}}` 도 벗긴다. HTTP 200 + `code: "error"` 등은 실패.
- 사용자 날짜가 `createdAt` (예전 DTO) 이면 `createddate` 로 바꾼다. 비밀번호 필드는 버린다.
- 실패는 4xx + `{message, fieldErrors?}` 를 권장한다 (폼에 필드별 에러를 보여준다).
- Go `auth error` (HTTP 200)는 권한 부족(남의 글)일 수도 있어서 로그아웃하지 않는다. 토큰 만료는 401 로 알려야 한다.

## 이미지 업로드

게시글 `img` 컬럼에는 업로드한 파일 이름을 넣는다. `POST /api/upload/index` (multipart, 필드 `upload`) → `{filename}`
(`basicproject_go`). 업로드는 gomachine 계약 밖이라 다른 백엔드에는 없을 수 있다 (`src/api/upload.ts` 만 고치면 된다).
화면은 `/uploads/{img}` 로 보여준다 (`lib/format.ts` 의 `imageUrl`).
